# 批量生图提示词文件提交

## 启用 Auto 尺寸

质量 `auto` 与尺寸无关。按提示词决定画幅时，分辨率和比例都选择“自动（Auto）”；任务保留两个 `auto`，上游请求发送 `size=auto`，不追加固定比例或清晰度要求，不解析或改写原始提示词。Auto 不保证精确像素、厘米或 DPI。

仅有调用代码支持不够：站点规格、模型关联及价格矩阵必须同时配置，否则页面没有选项或提交时报未配置价格。`scripts/enable-image-auto.sql` 提供显式选择站点和 GPT Image 2/2.5 模型的配置操作；默认使用者应先传 `apply=false` 预览。需要提供 `site_id`、逗号分隔 `model_ids`、`baseline_resolution` 和 `apply` 四个 psql 参数。

Auto 分辨率复制所选基础分辨率的最新有效价格；Auto 比例保留相应分辨率的价格。脚本要求每个分辨率不同画幅价格一致且基础档位覆盖完整，遇到歧义事务回滚。既有价格、历史任务和其他站点不修改；重复执行不重复插入，也不覆盖已配置的 Auto 价格。以后仍通过后台管理规格及价格。

测试站本次选择 site 1 的模型 57、150、151、152、153、154，基础档位 `1k`。这是测试站配置，不是面向其他站点或生产环境的自动迁移。

前端继续支持粘贴提示词和现有 TXT / CSV / Excel 导入。提交时，浏览器自动生成 UTF-8 JSON 文件，通过 `POST /image-tasks/batch-upload` 的 multipart `manifest` 文件字段上传。用户无需手工创建 JSON。

文件格式：

```json
{
  "version": 1,
  "work_type": "batch_generate",
  "batch_id": "batch-unique-request-id",
  "model_id": 57,
  "resolution": "1k",
  "aspect_ratio": "3:2",
  "quality": "auto",
  "prompts": ["第一条提示词", "第二条提示词\n其内部换行"]
}
```

每个数组元素是一项任务。粘贴输入保持原有每行一项的规则；文件协议允许元素内部包含换行。格式、非空内容、数量、大小、模型、规格、站点权限、价格、队列容量均由后端复核。文件默认最多 64 MiB，每条最多 100,000 字符；任务数量遵循站点配置，批量文生图硬上限为 20,000。

成功保存 `image_batch_uploads` 后返回 HTTP 202，响应包含 `batch_id`、`task_count`、`submission_status`，`tasks` / `task_ids` 初始为空。此时尚未生成图片、扣费或创建子任务。前端通过现有批次列表与状态接口恢复进度，刷新页面不会丢失已接收的批次。

后台与生成调度器一起启动，使用 PostgreSQL 会话 advisory lock 协调多个进程。状态为 `queued → processing → debited → submitted`。外部钱包、单项价格和任务执行策略在接收时冻结；外部钱包整批扣一次，每条任务仍有独立本地账本和退款凭证。所有子任务、账本、退款凭证和 `submitted` 状态在同一事务提交，然后交给已有生成队列。生成并发限制不变。

相同用户、站点、批次编号和内容重复上传返回原批次；内容改变返回 409。旧 JSON 批量接口继续可用，并识别相同编号的已上传批次。未拆分的文件任务数计入现有账号队列限额，容量检查使用单次数据库快照。

创建失败且已确认外部扣费时，先持久化 `compensating`，再按固定幂等键整批退款。退款响应丢失后继续该阶段，不会重新扣费。外部扣费响应不确定时，只重试原幂等键；达到重试上限进入 `needs_attention` 并保留 `recovery_phase`，前端显示批次编号和联系客服提示。不能将未知扣费结果直接当作未扣费重新提交，也不能盲目退款。完成或确定失败时清除重复保存的提示词数组，任务表保留每项原文。

配置：`BATCH_UPLOAD_MAX_BYTES`（默认 64 MiB，可配置 1 KiB–128 MiB）、`BATCH_UPLOAD_MAX_PROMPT_CHARS`、`BATCH_UPLOAD_WORKER_INTERVAL_SECONDS`（默认 2）、`BATCH_UPLOAD_WORKER_MAX_INFLIGHT`（默认 2）、`BATCH_UPLOAD_WORKER_MAX_ATTEMPTS`（默认 3）。上传上限须低于前端 Nginx 的 65 MiB 请求上限（如调高文件上限，同步调整反向代理限制）。未确认批次继续占用队列容量，防止反复提交绕过限额。

发布通过 Git push / 生产 git pull；用户服务启动前执行 Alembic `20261010_0100` 迁移。新表是增量迁移，旧服务可以保留该表后回退运行；回退前必须先停止接收新批次并等待文件批次提交或补偿完成，再确认生成队列排空。不要在有待处理批次时删除此表或降级迁移。

验证包含真实 PostgreSQL 的 500 条长提示词、2,000 条边界、并发上传重试、跨站点权限、队列预留、扣费与退款响应丢失、创建事务回滚、扣费后重启恢复，以及页面重新挂载和进度转换。不会为验证重放真实用户的付费批次。


## 单列系列文件与下载（2026-10-12）

批量文生图支持单列 XLSX / XLS / CSV：首个非空行为 `【文件夹名称】`，后面一行一条提示词；之后遇到整行 `【新的文件夹名称】` 时切换目录。空行跳过，单元格内换行保留，不解析提示词里的尺寸、比例或 DPI。旧「提示词」表头模板和普通 TXT 仍可导入。命名格式拒绝额外非空列、公式、错误单元格、无提示词目录、非法路径和超限文件。文件名与 Excel 内容签名必须匹配。

浏览器提交 `prompts` 和等长的 `folder_names` 数组；后端再次校验名称和长度，并纳入幂等内容哈希。目录信息复用任务 `input_group_id` / `input_group_name`，不需要增加数据库字段。大批文件在页面显示数量和首条预览，避免渲染全部长提示词；可清除重填或重新导入。

文生图整批下载查询可见范围内的全部任务，ZIP 根目录包含各 `【系列名称】/` 图片目录，以及且仅有 `完整汇总.xlsx`、`失败汇总.xlsx`、`结果统计.txt`。汇总包含原提示词、目录、任务编号、图片路径、状态和失败原因；生成失败和下载失败均记入失败表。进行中的任务明确记为未完成，不计作失败或成功。超过 Excel 单元格 32,767 字符的提示词分为有序续列，避免截断；提示词作为文本写入，禁用公式和自动超链接。

文生图下载采用 ZIP64 流式响应、受控图片预取和磁盘临时 Excel，不在浏览器或服务器内存中积攒整个压缩包。`IMAGE_EXPORT_STREAM_MAX_BYTES` 默认 100 GiB，只用于此流式路径；旧内存导出仍受 `USER_IMAGE_EXPORT_MAX_BYTES` 的 512 MiB 限制。下载失败只记录错误，不重新生图或扣费。客户端中断后清理临时文件，导出槽位保留到在途读取结束。

部署配置须同时确认：站点「单次批量任务上限」至少 20,000、`USER_IMAGE_TASK_QUEUE_LIMIT_PER_USER` 至少 20,000、`BATCH_UPLOAD_MAX_BYTES` 至少覆盖完整 JSON 大小、各层代理允许该上传大小。已有站点限额和已有环境变量不会被代码静默覆盖。管理端已允许设置至 20,000。

本地测试使用真实 PostgreSQL 验证 10,000 条入库与目录关联、幂等重试和账本一致性；`scripts/benchmark_prompt_export.py` 通过本地 HTTP 下载生成的测试 PNG（不调用付费模型），验证 10,000 图片、500 目录和超过 4 GiB 的 ZIP64。2026-10-12 本机结果：5,263,222,515 字节、116.13 秒、首字节 1.60 ms、峰值 RSS 170.44 MiB、最高 4 路下载、事件循环最大延迟 201.88 ms、所有 ZIP CRC 校验通过。这不是公网/CDN吞吐或线上容量承诺。

`auto` 处理：Images API 显式传 `size=auto`，不再回退为固定方图；GPT chat 请求也显式传 `size=auto`，不追加像素宽高。非 GPT 的自动项不追加提示词尺寸约束。模型和价格仍须在后台配置对应选项；不会从提示词推导计费档位或新增价格。


上游能力核对：`v4-gateway/src/image_parameters.rs` 保留显式 `size=auto` 并使其优先于固定比例/分辨率别名；`chatgpt2api-v4/src/image_adapter_args.rs` 的直接 Chat 适配当前不复制顶层 size，普通 `gpt-image-2` 网页路径因此按提示词决定画面，不会执行本地像素重设。`codex-gpt-image-2` 是不同原生路径，缺少 size 时默认 `1024x1024`，不能据此承诺所有 chat 模型行为一致。尺寸自动不等于保证印刷厘米尺寸或 300 DPI 元数据，需核对实际输出。

回归检查：本次批量上传、目录持久化、导出、失败重试、隔离权限与 auto 请求相关检查通过；用户端 Vite 构建、用户端和管理端 TypeScript 检查通过。扩展运行 `test_image_generation.py` 时有 6 项既有失败（错误文案、回收间隔、视频测试桩/行为）；用 Git HEAD 版本的生成模块复现了同样 6 项失败，本次未改动这些行为。


## 两万条与浏览器 CDN 下载（2026-10-12）

单批文生图及账号待处理队列默认上限调整到 20,000，仍按现有模型/用户并发执行；不提高生图并发。上传仍保留 64 MiB 文件上限和每条 100,000 字符校验，过大时明确拒绝，不部分提交。

批量文生图的下载按钮使用电脑端 Chrome/Edge 的保存文件能力。用户选择 ZIP 保存位置后，`GET /image-tasks/browser-export/items` 按最多 200 项分页返回有权限的任务、CDN 地址、目录和状态，不向浏览器传整批提示词。首次最大任务 ID 固定分页范围；每一页、每份汇总均重新验证站点/团队权限。

浏览器直接从 CDN 获取原图，不携带应用 JWT 或 Cookie，不经过服务器图片代理。下载预取最多 4 张，按单图上限将预取有效载荷预算控制在 128 MiB（当前单图上限 64 MiB，对应 2 路）；运行时另有 JS、Blob 及 ZIP 索引开销。图片不重编码，使用 ZIP64 无压缩写盘；不构造整包 Blob。下载中显示已处理数量、成功/失败和已写入图片字节，可取消。同页只允许一个批次下载。

暂时性 CDN/网络错误最多重试 2 次，仅重试图片 GET，不重新生图。完整读取并确认图片格式后才写 ZIP；缺失、超限、无跨域权限、格式错误等记录进失败汇总。磁盘写入、清单或汇总获取失败会中止整个保存，不能伪装成功。

图片保存后，浏览器将下载结果提交到 `POST /image-tasks/browser-export/reports/{full|failed}`；服务器只读取可见任务的提示词元数据并生成 XLSX，不下载任何图片。XLSX 以响应流写入最终 ZIP，连同浏览器生成的 `结果统计.txt`，保持原有三个汇总文件及系列图片目录。失败表覆盖生成失败和 CDN 下载失败，进行中任务标记未完成。

限制：需要允许浏览器跨域读取的 CDN；不支持本地大文件保存能力的浏览器显示 Chrome/Edge 使用提示，不静默回退服务器中转。下载期间需保持页面打开，当前无跨会话断点续传；请预留足够磁盘空间。2026-10-12 对测试站实际 CDN `openagent-cdn.shyfai.cn` 携带站点 Origin 验证返回 `Access-Control-Allow-Origin: *`，这不代表公网速度保证。

验证：真实 PostgreSQL 的 20,000 条任务/目录/账本幂等测试通过；浏览器下载核心的 ZIP64、分页、身份隔离、失败汇总、取消、磁盘失败、单图超限及仅 GET 重试测试通过。`scripts/benchmark_browser_export.mjs` 使用相同前端导出实现，在 Node + 本地 HTTP 环境验证 20,000 张、1,000 目录、5,414,621,745 字节 ZIP，36.49 秒完成，首字节 7.78 ms，进程峰值 RSS 536.27 MiB，100 页元数据，最高 2 路下载，全部 ZIP CRC 通过。这个数值包含测试程序和汇总样本，不代表实际浏览器内存或公网/CDN吞吐。

真实浏览器补充验证：Chrome 154（独立持久化测试 profile）使用浏览器原生 FileSystemWritableFileStream 写入 OPFS 临时文件，20,000 张、1,000 目录、5,413,496,679 字节 ZIP，105.21 秒完成；100 页清单、21,003 ZIP 条目、统计一致，抽样 101 张图片 CRC 通过。下载及后续校验期间 JS 堆峰值 301.53 MiB，事件循环最大延迟 383.30 ms；JS 堆不等于浏览器进程总内存。本项测试报告文件使用占位数据，真实 XLSX 内容由后端集成测试覆盖，Node 压测验证整包所有条目 CRC。初次无痕上下文的 OPFS 测试触发配额限制；改用独立普通 profile 的 10 GiB 配额后完成，本次产品使用用户选择的磁盘文件，不使用 OPFS 储存整包。临时 ZIP 和浏览器 profile 均已删除。
