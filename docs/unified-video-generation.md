# 统一视频生成与参考素材

2026-11-10，基于生产提交 `f475c1315d9677e7671cfc5b18477c34e782bc91` 开发。尚未部署。

## 页面与接口

- 入口为 `/create/video`，原 `/create/text-to-video`、`/create/image-to-video` 重定向到同一页。
- 素材选填。无素材提交 `text_to_video`，有素材提交 `image_to_video`，报价同步采用对应类型。合并查询两种历史任务。
- `/models?work_type=video` 返回两种视频模型的合集，以及实际 `supported_work_types`、`reference_capabilities`。`video` 只用于目录查询，不可作为计费任务类型。
- `POST /uploads/video-references` 接受 multipart `file` 和 `model_id`，校验站点、用户、模型公开状态与文件字节，复用模型的 CDN/存储配置。保留现有图片上传接口。
- 继续用既有资产 ID 和任务 URL 字段保存参考素材，无表结构迁移。提交时重新校验资产归属、类型、数量、单文件/总大小；图片任务拒绝音视频资产。
- 已核对 FF/Muse V4 的 `reference_media: [{url, kind}]` 合同。Magic 按顺序传递实际媒体类型；Veo Lite 的首尾帧顺序由 V4 解释。接入层保留此字段。
- 下载校验逐个进行，URL 素材不在内存累积整组音视频字节。此类视频创建固定使用 `/v1/videos`，不因未知提交结果改换请求体/端点重新创建任务。
- 上传期间禁止提交和切换模型；部分上传失败保留成功素材。切换到不兼容模型保留素材并阻止提交，允许删除、重新排序。

## 主站开放范围

| 模型 | 素材 | 限制 |
| --- | --- | --- |
| Veo Lite | PNG/JPG | 首帧、尾帧共 2 张；每张 50MB |
| Omni Flash | PNG/JPG、MP4/MOV/WebM | 共 10 个；其中视频最多 3 个；每个 50MB |
| Muse / Muse CDN | PNG/JPG/WebP/GIF、MP4/MOV/WebM、MP3/WAV/M4A/OGG | 共 4 个，合计 24MB |

其他模型保持后台已发布的能力。代码包含已有 V4 Seed20/Seed25 合同的数量/大小及音频搭配视觉素材校验；主站配置脚本不发布这些模型。

## 发布步骤

遵循 [维护发布流程](08-maintenance-deployment.md)，代码必须通过 Git 发布。

1. 备份主站目标模型和价格配置，确认 FF/Muse V4 已部署媒体参考支持。
2. 发布 `user-server`，验证新素材上传接口和视频模型目录；排空旧 worker 时保留所有在途任务和已接受的上游任务 ID。
3. 在服务器已拉取的 Git checkout 执行 `scripts/unified-video-references.sql`。脚本仅处理主站 `site_id=1` 已启用且公开的 Veo Lite、Omni、Muse、Muse CDN，不激活其他模型。缺少的参考生成价格复制同规格当前文生视频价格；已有参考价格保留。没有基础价格时整笔事务失败。
4. 发布 `user-web`。验证两个旧地址、无素材、有图片、有视频、有音频、异步查询和结果下载。
5. 线上真实生成验证仍需在发布后执行。尤其 Omni 视频参考此前存在上游 `408 system under load`，本改动不代表该上游问题已经恢复。

回滚前应排空新提交的混合素材任务；旧 worker 不认识这些素材的序列化合同，不能直接接管它们。已接受任务只恢复原任务查询/交付，不重复生成。
