# 用户 Key 分组白名单

后台 Agent 配置保留文本、图片两个默认分组，新增可多选的 Key 分组白名单。默认分组自动勾选、不可取消；额外分组可独立添加或移除。用户创建 Key 时看到“两个默认分组 + 额外白名单”中上游当前可用的分组。

`agent_configs.key_group_whitelist` 保存按站点隔离的额外分组 ID（JSONB 数组）。默认分组运行时合并，不重复写入该数组，切换默认分组也不会把旧默认项永久留在白名单。老客户端不提交该字段时保留已有配置。最多 200 个额外分组；拒绝非法 ID、新增的未知/停用分组。切换 Agent Base URL 时会重新验证已有白名单，避免把另一个服务的分组 ID 当成新服务的授权。

用户初始化和账号同步会同步扩展后的上游 allowed_groups；默认仍只自动创建文本、图片两把 Key，不为每个白名单分组自动创建 Key。用户手动创建和切换 Key 分组必须通过服务端白名单校验。

移除白名单不会删除或主动停用已有 Key。已有 Key 仍显示其分组，可改名称、额度、状态等；再次新建该分组或从其他分组切入会被拒绝。上游自行停用/删除分组仍受上游状态约束。

团队额度保留原有分类：默认文本分组使用文本额度，其他分组纳入图片/视频额度。额外分组和已移出白名单的历史 Key 也参与该类别的额度分配与用量统计，不能通过切换分组重复取得成员总额度。未增加每个分组独立的额度池。

本次发布已合并七天保留改动，用户端通过 `20261019_0300` 合并两个迁移 head；管理端 head 为 `20261019_0200`。自动清理保持默认关闭，历史列表的七天过滤随应用发布生效。

验证包括数据库迁移、后台配置持久化/站点隔离/旧客户端兼容/无效分组拒绝、用户创建和修改 Key 授权、账号同步以及团队额度。两端 DOM 交互测试分别验证默认项不可取消、额外项保存后重载，以及用户创建弹窗显示新增分组。两端前端类型检查和构建通过。测试上游均使用替身，未操作生产上游账号或 Key。
